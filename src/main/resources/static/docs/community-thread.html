1. 연결

CONNECT header: Authorization: Bearer <access-token>

토큰은 이 페이지의 메모리에서만 사용하며 저장하지 않습니다. 공유 화면이나 운영 토큰으로 테스트하지 마세요.

2. Command 전송

전송 시도마다 commandId는 새로 만들고, 생성 retry에서는 payload의 clientMessageId를 유지하세요.

메시지 생성 payload 
{
  "clientMessageId": "lowercase UUID",
  "type": "TEXT | IMAGE",
  "content": "본문 또는 이미지 캡션",
  "fileMetadataIds": [],
  "mentionedMemberIds": [],
  "replyToId": null
}
  • TEXT: content 필수, fileMetadataIds는 비어 있어야 합니다.
  • IMAGE: fileMetadataIds 1~4개가 필수입니다.
  • 같은 clientMessageId retry는 type/content/files/mentions/replyToId가 동일해야 합니다.
수신 event envelope 
{
  "eventId": "UUID",
  "type": "message.created",
  "threadId": "100",
  "occurredAt": "2026-07-21T04:00:00Z",
  "payload": { ... }
}

type은 command.acknowledged, message.created/updated/deleted, reaction.changed, read.updated, thread.invited/updated/deleted, member.kicked/left 중 하나입니다.
