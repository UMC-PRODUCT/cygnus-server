Official Firebase documentation checked:
- https://firebase.google.com/docs/cloud-messaging/customize-messages/set-message-type
  - Notification messages may be handled/displayed by the SDK in background; data messages are handled by client code.
  - Firebase notes that FCM transport is not end-to-end encrypted and reserved keys such as `from`, `gcm`, and `google` should not be used in custom data.
- https://firebase.google.com/docs/cloud-messaging/android/receive-messages
  - Android background behavior differs for notification/data payloads; notification payload can be delivered to the notification tray and data payload can be exposed through intent extras.
  - Android-specific notification icon/color/default appearance are configured through Android-specific options/resources.
- https://firebase.google.com/docs/cloud-messaging/ios/receive-messages
  - iOS silent/background update behavior requires APNs-specific `content-available`.
- https://firebase.google.com/docs/cloud-messaging/customize-messages/cross-platform
  - Cross-platform messages can use common notification/data fields plus platform-specific `android` and `apns` blocks.
  - Firebase documents platform-specific click action/category handling.
